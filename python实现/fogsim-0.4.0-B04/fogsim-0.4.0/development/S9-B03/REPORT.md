## 失败、中断与修复

1. 初始高负载场景（workload500..1500）的首个任意双树在本地组件运行中耗时过长，测试命令被人工中止，最后完整提交到评估初始快照及活动配置（尚无完整原结果）。另用3秒堆栈/5秒中止诊断实际观察到187事件、32生成工作流、仅1个统计完成，堆栈在B08图只读保护。保存partial原结果/输入、异常、命令和初始配置，不伪装为领域失败或完整可重放输入。
2. 正式冻结前只把工程工作量范围降到50..150，其余拓扑/资源/到达分布/统计/事件上限/GP评分/只读保护均不改。相同诊断表达式成功：26事件、4生成工作流、2统计完成；随后开发组件41项通过。不是按最终测试结果更换候选或调参，正式配置在任何正式训练之前固定。
3. 新增计数案例曾因测试把subtree来源当作parent字段读取而KeyError，修正字段访问；生产算子未改变。新增42项最终通过。一次wheel构建命令缺本地路径./标记，原错误保存，纠正命令后构建/安装通过。
4. 正式冻结后生产源码无变更，单树/双树专项、Java、正式首跑/复跑、兼容回归均绑定同一源码。未知程序异常、回调异常、事件失败、验证全不可行、最终测试失败及墙钟路径按原合同保存并停止，不制造正常冠军，不因测试失败换候选。
