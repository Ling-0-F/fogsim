## 1. 目标与当前范围

最终目标是在 Python 中复现该 Java 项目实际使用的工作流模型、动态调度模拟、调度规则、GP 表达式求值、单树/双树演化、训练评估和实验分析。

当前先实现固定小实例模拟器，之后加入随机实例和 GP。完整复现以行为为单位，不要求复制整个 ECJ 通用框架、教程和继承体系。用户已完成原阅读计划中“第 6 步：路由与排序规则接口”的学习，当前处于阶段 A/B 的实践准备。

## 3. 当前设计基线

1. 建议目录 fog-computing-python，包名 fogsim；现有文件职责和字段允许在记录理由后修订。
2. 0.1 先跑通固定输入、单任务/链式工作流、四种事件、本地/远程执行、FCFS 和完整日志；0.2 验收 DAG 分叉汇合、竞争、同时刻事件及 Java/Python 对照。
3. 初始 M0、E0、C0 各一个，通过列表表达；时间直接给定，之后才引入工作量、数据量、速率及带宽计算。
4. 非抢占；资源同一时刻执行一个任务；计算与下载均计入资源占用。移动设备只处理自身工作流，服务器为共享候选。
5. 0.1 全部固定输入参与统计、无 warm-up；未到达工作流不能供当前规则读取。
6. Task 保存派发/完成标记；TaskOption 保存 ready_time 和最近评分；Resource 保存资源时间、等待队列、缓存、完成任务数及 pending_start。
7. SystemState 保存时钟、生命周期集合、模型索引和执行登记索引；Engine 管理事件、运行控制并持有 TraceRecorder。
8. 固定实例重跑从同一 InstanceSpec 新建独立运行对象图；RNG 重设、继续随机流与 seed 轮换另行区分。
9. pending_start 属于 Python 显式保护设计，其与 Java 同时刻边界路径的等价性尚待验证；本地和服务器缓存维护按源码保留差异。
