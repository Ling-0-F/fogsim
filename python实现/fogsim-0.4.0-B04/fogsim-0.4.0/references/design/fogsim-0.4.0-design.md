## 4. 个体、树、规则与身份

### 4.1 表示与统一角色映射

规则安装和协议始终按明确的 `sequencing`、`routing` 角色命名。数组下标只表示当前模式中的基因组位置，不能脱离模式推断角色。

| 模式 | 可变基因组位置 | 角色 | 传给 B08 的规则对 |
| --- | --- | --- | --- |
| `single_routing` | 唯一一棵树，局部位置 0 | routing | routing=GP；sequencing=显式 FCFS |
| `dual_tree` | `trees[0]` | sequencing | 与 `trees[1]` 一起组成同一规则对 |
| `dual_tree` | `trees[1]` | routing | 与 `trees[0]` 一起组成同一规则对 |

双树共享一份个体评估结果，作为一组规则执行和选优。不把两棵树拆成两个种群，也不按 DEAP ADF 的主程序/子函数关系解释。单树转双树及规则导出时统一通过角色适配表，不能把单树局部位置 0 误作 sequencing。

### 4.2 可变训练结构与不可变执行结构

DEAP 树可变，B08 AST/程序不可变。交叉、变异、复制、失败回退和精英保留均产生独立的可变树；父代、兄弟子代、历史记录和候选快照之间不共享可变树。

转换保留节点类型、左右次序、重复叶和常量位模式，不进行代数化简、公共子表达式合并或常量折叠。真实调度不使用 `gp.compile()`，也不执行来自文件的任意 Python 表达式。

历史快照必须脱离可变个体对象图。共享不可变执行对象仅能依照 B08 的不可变合同，不能借此共享后续要修改的 DEAP 树。

### 4.3 终端与函数

执行集合沿用 D-frozen-1：

- 十特征：`NIQ, WIQ, MRT, UT, DT, PT, TTIQ, TIS, TWT, NTR`。
- 六个严格二元函数：`+, -, *, /, Max, Min`。

DEAP 内部函数名称与 B08 token 的映射须显式固定；序列化和执行均使用确定的映射，不依赖函数对象的偶然名称。

首版演化只抽取十特征，不启用随机数值 ERC。固定规则评估仍可使用 B08 已支持的常量；适配往返不能丢失常量的 binary64 位模式。Java `TerminalERCUniform` 在本配置中是特征抽样入口，其名称不表示开启随机数值常量搜索。

### 4.4 身份分层与冻结要求

| 身份 | 定义及用途 |
| --- | --- |
| B08 `expression_id`、`rule_id`、`rule_pair_id` | 完全复用既有规则协议，不混入 seed、代数或适应度 |
| `individual_id` | trial 内的出生身份，包含 trial、出生代和稳定序号；相同规则可以有不同出生身份 |
| `scene_id` | 场景有效参数、模板内容、统计及运行预算的内容身份；排除规则、seed、split 和输出位置 |
| `input_family_id` | 仅含输入生成参数、环境配置及模板内容；排除规则、统计目标、事件预算、split 和输出位置，用于划分检查 |
| `plan_id` | split、有序运行条目、生命周期及评估策略版本的内容身份 |
| `evaluation_id` | 规则对、plan、实现/策略版本与 trial 内评估序号的绑定 |

新身份使用独立域前缀及规范化 JSON 的 SHA-256，不能冒用 B08 的摘要域或使用进程随机 `hash()`。对象键排序、数组保留顺序，UTF-8 编码；缺失值与 null 不混同；禁止裸 NaN/Infinity。特殊规则分数如需进入明确的诊断字段，按 B08 位串标签处理。

精确的规范化字段表、域前缀和协议 schema 随相应批次实现一并固化、留出测试向量；一经产生正式证据，不得静默改变。工程细化不得改变本节各身份的纳入和排除原则。

首版不做跨个体或跨代适应度缓存。即使规则身份相同，也按本代计划完整评估。以后如加缓存，键至少包含完整计划、生命周期、资源上限和失败策略，不能只用规则身份。

## 5. 训练、验证、测试与计划

### 5.1 清单结构与冻结

一条 `RunPlanEntry` 至少包含：稳定 `run_id`、`scene_id`、`input_family_id`、有效场景配置及摘要、模板摘要、模式、显式 seed 或输入档案内容摘要、统计设置、确定性事件预算及生命周期。

主训练生命周期为 `fresh_dynamic_same_plan`。固定输入和重放用于评估测试及受控对照；未经覆盖核验的有限重放记录不能作为默认种群训练输入。

所有需要的训练计划、验证和测试清单均在训练前展开、检查并冻结。计划生成不消费进化 RNG，不因个体执行次序而改变。公共 seed 满足 B08 有符号 64 位合同；训练清单的算术溢出明确拒绝，不自行取模。

### 5.2 每代计划与 seed 派生

代号为 `g=0,...,G-1`；`generations=G` 表示恰好评估 G 个种群，包含初代。`rotation_period` 为正整数，默认 1。

训练条目 j 的初始 seed 为显式给出的 `b_j`，第 g 代使用：

\[
s_{g,j}=b_j+10000\left\lfloor\frac{g}{\text{rotation\_period}}\right\rfloor.
\]

派生使用明确的整数运算，在冻结清单前检查每一条结果的 signed64 范围及跨 split 重复。相同周期内复用相同训练计划属于预期行为；不得因此复用上代成绩。

| 代数，默认周期 1 | 条目 1，`b_1=101` | 条目 2，`b_2=102` |
| --- | ---: | ---: |
| 0 | 101 | 102 |
| 1 | 10101 | 10102 |
| 2 | 20101 | 20102 |
| 3 | 30101 | 30102 |

每代开始确认其 `plan_id`，全种群重新评估，包括精英和原样复制个体；周期大于 1 时仍如此。最后一代评估结束后不再繁殖、轮换或生成不使用的下一代运行计划。

验证、测试清单固定，不随训练轮换。每次独立训练的 evolution seed 另行指定，不由模拟 seed 或计划展开过程隐式派生。

### 5.3 “同一计划”的含义

同代个体共享场景、seed 条目、统计设置、运行资源上限及 fresh 初始化方式。每个个体、每条运行创建独立上下文，初始统计边界 B 来自 fresh 创建，不继承上一个体的 B、队列、环境实例或 RNG 游标。

B08 动态输入按模拟过程需要生成，规则可能改变调用顺序和实际消费的输入。默认承诺是“同计划、同输入生成机制”，不声称不同规则实际见到的完整工作流序列逐条相同。

严格共同输入实验须保存明确固定输入，或证明重放源覆盖所有被比较规则，声明 `input_contract` 并与默认动态训练结果分列。某条规则的有限捕获不能自动视为另一条规则的完整输入。

### 5.4 划分隔离

拒绝跨 train/validation/test 重复的 `(input_family_id, seed)`，以及相同完整输入内容身份；路径不同但内容相同的档案也须识别。不能只因统计目标或事件预算不同，就把同一随机输入来源认作独立划分。

同一公开场景配置可用于三个 split，但随机实例清单独立。验证和测试运行数、seed 在训练前确定；测试不用于早停、参数调整、挑选代数或挑选演化重复。

三类清单独立并不要求拓扑类型或资源规模完全不同，也不自动构成未见场景泛化实验。多个 trial 可以共享同一套模拟计划；该安排需记录，跨 trial 共享不能误报为跨 split 泄漏。

### 5.5 旧数据角色兼容

B08 `OutputConfig.dataset_role` 仍仅支持 debug/train/test。训练层独立保存精确 split，不向旧 schema 偷加 `validation`。

| 训练层 split | B08 档案 `dataset_role` | 解释 |
| --- | --- | --- |
| train | train | 训练用途 |
| validation | debug | 兼容旧枚举；训练计划明确声明真实 split 及映射原因 |
| test | test | 最终测试用途 |

训练层 split 是权威划分记录，不能仅凭旧档案的 debug 字段判断用途。将来若要在 B08 档案直接表达 validation，须单独设计协议版本，不能改写历史档案。

## 6. 随机流和生命周期

### 6.1 两类随机流

| 随机状态 | 用途 | 约束 |
| --- | --- | --- |
| 进化流 | 随机树、父代、算子、树槽、节点和变异内容 | 独立 evolution seed；保存状态或状态摘要 |
| 模拟输入流 | 设备/服务器环境及动态工作流输入 | 每条运行由其公共 seed 独立创建；沿用 B08 编码 |

两类流可以使用同一 RNG 算法或公共工具，但不能共享可变状态。多一次进化抽样不能推进模拟输入流，多一次模拟或更多事件不能推进进化流。三类计划不通过进化 RNG 生成。

### 6.2 DEAP 模块级 random 与工作进程

DEAP 的多个内置组件使用 Python 模块级 `random`。不能只创建一个未被这些组件使用的 `Random` 实例就声称完成隔离。

一次独立演化重复在一个串行 spawn 工作进程中执行。该进程统一设置并管理 DEAP 所用的进化随机状态，模拟继续使用 B08 自己的 `Random` 对象。父进程只承担控制、证据接收、进度回调和墙钟监督，不消费进化随机数。

多个 trial 默认顺序执行。这是随机状态和运行状态的隔离措施，不是并行加速方案。训练不能污染调用进程的模块级 random 或旧 API 已有的 RNG 对象；未知异常和进程异常退出按第 7 节处理。

### 6.3 fresh 主路径与 Java 生命周期

主训练每个个体、每条运行均通过新建 `create_dynamic_context()` 开始。本阶段不新增 `java_lifecycle` 训练模式，不用 reset/rerun/rotate 替代 fresh。

Java 生命周期的源码观察如下。B 是既有 recorded 统计使用的释放时间边界。

| 操作 | 资源环境 | 模拟输入 RNG | B |
| --- | --- | --- | --- |
| 新建模拟器 | 按 seed 采样资源参数 | 从 seed 开始，先消费资源采样前缀 | 从初始值开始，随后由输入生成更新 |
| `run()` | 使用已准备环境 | 从当前状态继续 | 使用当前状态 |
| `rerun()` | 保留环境参数，清空运行状态 | 继续原随机流 | 重置代码不主动清零，随后可能由新输入更新 |
| `reset()` | 保留环境参数，清空运行状态 | 重新设置为当前 seed | 同上 |
| `rotateSeed()` | 保留环境参数，清空运行状态 | seed 加 10000 后重新设置 RNG | 同上 |

reset/rotate 不重新采样资源，因而不会再次消费资源采样前缀。同 seed 的 fresh 与 reset 不能直接视为同一输入过程。沿用 seed 的 10000 步长不意味着主训练改用 Java 的状态复用生命周期。

必须另做独立、可运行的小型生命周期对照，记录新建、run、rerun、reset、rotate 前后的 seed、资源摘要、B、运行状态和 RNG 状态/指纹。示例序列为：新建 → 运行 A → rerun → reset 后运行 B → rotate 后再运行；在操作边界和运行边界均取证，区分重置本身和随后生成输入的作用。

默认 fresh 另验证交换个体 A、B 的评估顺序不会改变各自结果。Java 与 Python 的原生随机序列不要求相同；比较状态合同和受控输入下行为。B08 已有轮换 API 的 Java long 回绕语义保持不变，单独验证；训练清单展开的溢出拒绝合同见第 5 节。

## 7. 适应度评估、失败与汇总

### 7.1 调用链

1. 检查树结构、角色与演化资源限制，转换规则并准备 `PreparedRules`。
2. 绑定不可变计划及规则对身份，创建本次评估记录。
3. 按清单顺序生成有效 B08 v2 配置，每条 `repeat.count=1`、公共 seed 明确；活动配置的规则须与 `PreparedRules` 完全一致。
4. 每条运行新建上下文并执行，保存原结果、输入来源及必要档案。
5. 按本节区分成功、领域失败和中止，不吞掉原始异常信息。
6. 计划结束后生成结构化评估结果，交给选优层；不把训练字段写回旧 RunResult。

多场景计划按条目调用模拟器，由训练层聚合。可复用旧 runner 的适用功能，但不得绕过其同场景兼容约束，也不得使用成功子集均值完成训练选优。

### 7.2 指标与公式

动态运行直接读取 B08 makespan：

\[
m_j=\max_{w\in R_j} C_w-\min_{w\in R_j} r_w,
\]

其中 `R_j` 是 B08 按既有规则纳入统计的工作流集合。训练层不重选成员，不用最终模拟时钟替代 makespan，也不改为 mean flow time。固定模式的 makespan 仍按固定模式原定义。

计划含 K 条运行，K 至少为 1。只有全部 K 条成功且指标有效时：

\[
F(I,P)=\operatorname{mean}(m_1,\ldots,m_K)
=\frac{1}{K}\sum_{j=1}^{K}m_j,\qquad \text{越小越好}.
\]

实现采用与现有 runner 一致的 `statistics.mean`，记录 Python 版本；不改为未经说明的简单浮点累加。成功指标必须为有限非负数；成功结果缺少有效指标属于结果/评估合同错误，中止并诊断。

每条运行等权。某场景的条目更多时，自然占更大权重，不另做“各场景先平均再等权”的不同目标。

### 7.3 评估状态与比较

| 状态 | 正式适应度 | 后续处理 |
| --- | --- | --- |
| `FEASIBLE` | 全计划均值，有限值 | 参加可行个体比较 |
| `INFEASIBLE` | null，保留逐条结果 | 排在全部可行个体后 |
| `INCOMPLETE` | null，保存中止原因和完成范围 | 不用于继续训练选优 |

`FEASIBLE` 要求 `completed_runs=planned_runs=succeeded_runs`。领域失败后继续剩余计划以收齐证据；不可行标记不会因后续成功恢复。未知异常或监督中断立即停止，本次评估记为 `INCOMPLETE`，并保留此前领域失败事实。

基本优劣只比较：可行优先；两个可行个体比较平均 makespan；两个不可行个体等优劣，不按失败次数或错误类型分级。平分须按使用场景分别处理：

| 场景 | 平分规则 |
| --- | --- |
| 锦标赛 | 保留本次有放回抽样中先遇到的个体；不得再用出生序号推翻 |
| 精英、本代最优候选等稳定排序 | 按稳定出生序号 |
| 验证选优 | 按候选首次出现次序 |

某代没有可行个体时，报告 `NO_FEASIBLE_INDIVIDUAL`，结束该次训练并保存种群和证据，不制造正常冠军。DEAP 的 `fitness.valid` 只表示其缓存状态，不能替代领域可行性。

### 7.4 失败分类

| 原因 | 训练处理 |
| --- | --- |
| 预检通过后，B08 返回约定的领域 FAILED，如确定性事件预算耗尽 | 本次个体评估不可行，保存原 FAILED 结果及 reason_code |
| 配置、模板、文件或来源准备缺陷 | 中止训练并诊断，不处罚个体 |
| 重放档案不足以覆盖改变后的规则 | 计划/覆盖错误，中止对照，不作为普通差适应度 |
| 算子替换超出树约束 | 按第 8、10 节回退；本应合法却解析失败属于实现缺陷 |
| 未预期程序异常 | 保留原异常链并中止，不能吞成领域不可行 |
| 墙钟超时、取消、工作进程异常退出 | `INCOMPLETE`，保存基础设施/中断原因，不作劣等适应度 |

当前领域失败统一执行 D03，不引入错误类型分级、自动重试或成功率折扣。

### 7.5 资源限制和墙钟监督

树高度、节点数属于确定性演化限制；模拟事件预算属于确定性运行限制，沿用 B08 的触发时点。有效配置、计划和评估绑定相应策略及预算，不能在身份不变时静默改变。

墙钟预算仅保护执行，不构成劣等适应度。父进程从已通知的运行开始监督；触发后终止该训练工作进程，原子保存已接收证据和中断记录，不拿不完整种群继续选择。首版没有任意位置续训；可在修正环境后从头同配置重跑。

合法的 NaN、正负无穷、负数及正负零规则分数继续按 D-frozen-1 执行，不能因规则分数非有限而判失败。普通 makespan 的有效性要求与规则分数数值合同分别检查。

### 7.6 报告统计

保存 planned/completed/succeeded/failed/not_run；失败率以 completed 为分母，未运行比例以 planned 为分母，无分母时为 null。

成功子集均值只作为 `diagnostic_mean_over_successes`，不得进入选优。样本标准差只在至少两条适用成功数据时计算，注明分母及统计范围。独立演化重复与个体内部模拟运行分别编号，不混为同一类样本。

每代计划变化时最佳训练值可以变差，不要求训练曲线单调下降。

## 8. 演化流程

本节是已确认流程，第 10 节给出 J01—J06 的来源及边界核验。使用自定义演化循环，不直接套用可能先交叉再变异的 DEAP 默认流程。

### 8.1 小规模默认参数

| 参数 | 确定值/含义 |
| --- | --- |
| `population_size` | 12，含精英 |
| `generations` | 4，评估第 0、1、2、3 代 |
| `independent_trials` | 2，使用不同 evolution seed |
| `elite_count` | 1 |
| `tournament_size` | 3；Java 对照配置为 7，可配置并留证 |
| 初始化 full/grow | 每棵各 50%，不强制种群精确各半 |
| 初始生成目标高度 | 在 1—3 中均匀选择；不是实际高度下限 |
| 每棵最大高度/节点数 | 7 / 255，分别检查 |
| 节点类别 | 函数 90%，特征叶 10%；根保留可选资格 |
| 变异新子树 | Java grow，生成目标高度上限 3，实际高度允许 0—3 |
| 交叉/变异尝试次数 | 各 1 次总尝试，不是失败后再额外尝试一次 |
| 算子选择权重 | 交叉 0.80、变异 0.15、复制 0.05 |
| 数值 ERC 搜索 | 关闭 |
| `rotation_period` | 1 |
| 运行数 | 每代训练计划 2 条；固定验证 2 条；最终测试 2 条 |

这些是工程 smoke 参数，不称为论文设定。用户后续可以修改规模，但不因种群或代数扩大而自动改变函数、终端、失败策略或统计语义。显式树/事件上限仍须执行。

### 8.2 初始化与树合法性

每棵树独立选择 full/grow 和目标高度。双树分别生成，按第 4 节角色映射安装。

- full：到目标高度之前只选函数，达到目标高度时选特征。
- grow：到上限前，在六个函数入口和一个终端入口中等概率抽取；终端入口概率为 1/7。选中终端后，再在十特征中等概率抽取。达到上限必须选终端。
- grow 可在根选择特征，因此目标高度 1—3 不排除实际高度为 0 的单特征树。
- 不采用将十个特征直接计为十个终端入口的 DEAP 默认 grow 概率。

高度按边数计：单叶为 0。初始化及每次操作检查高度、节点数、二元 arity、允许终端和角色，检查发生在进入模拟前。初始化配置预检和生成重试必须有有限上限；实际上限写入有效配置，耗尽后报配置/生成错误，不无限循环或静默放宽限制。

### 8.3 锦标赛和操作节点

每次锦标赛从本代种群均匀、有放回抽取指定数量个体，同一个体允许重复出现。按第 7.3 节比较；相等时保留本次抽样中先遇到者。两名交叉父代分别选择，允许相同，不因相同父代而改做变异。

交叉、变异节点先按 90%/10% 选函数/特征叶类别，再在类别内按节点位置等概率选择。重复出现的同一特征属于不同位置。单特征树没有函数节点，函数分支也回到其唯一根节点。

`root=0` 只表示不设“专门选择根”的分支，不表示禁止选根。函数根属于函数候选；单特征根是唯一节点。不得直接沿用 DEAP 默认交叉的排根候选集。

### 8.4 互斥算子选择与子代计数

每次需要填充非精英位置时，选择一个算子：

| 算子 | 调用选择权重 | 通常接纳子代数 |
| --- | ---: | ---: |
| 交叉 | 0.80 | 2 |
| 变异 | 0.15 | 1 |
| 复制 | 0.05 | 1 |

这些是算子调用的选择概率，不要求最终子代恰有 80% 来自交叉。交叉通常贡献两个子代；尾部容量、失败和回退分别记录。

只剩一个非精英位置时，交叉只输出子代 1，仅检查方向 1，不因未输出方向的失败否决它。失败回退所得克隆仍占正常子代位置，不自动补做另一个算子。

分别记录算子选择次数、接纳子代数和失败回退次数；回退按实际输出的子代方向记数。若另保存失败尝试数，须使用独立字段，不能与回退子代数混同。初始化和精英不计入三类繁殖算子的接纳子代数。

### 8.5 单树操作

单树仅操作 routing，sequencing 始终显式 FCFS。

交叉为普通子树交换，各方向独立检查。子代 1 尝试在 A 中接入 B 子树，失败则独立克隆 A；子代 2 尝试在 B 中接入 A 子树，失败则独立克隆 B。它与双树的特殊回退分别实现。

变异选择一个位置，用 Java grow 生成的新子树替换，目标高度上限 3。失败或超限时独立克隆原个体。复制保持规则结构，但产生新出生身份、独立树和待评估状态。

### 8.6 双树操作

交叉等概率选择 sequencing 或 routing，两个父代使用同一角色槽。在该槽进行子树交换，另一槽整体交换。各方向结果及失败回退严格按第 10.5 节分支表。

双树变异等概率选择一个角色槽，只变异选中树；另一树结构不变，但结果整体独立克隆。变异失败返回原个体完整规则对的独立克隆。复制同样克隆完整规则对。

### 8.7 精英与下一代布局

从本代可行个体中按均值、稳定出生序号选择精英，实际数量为配置数量与可用可行数量的较小值。精英不足的空位由普通繁殖填满；全代不可行时按第 7 节结束训练。

精英只保留规则结构，分配下一代出生/谱系记录，不沿用正式成绩。普通子代放前、精英放末尾；精英计入固定种群规模，不额外扩容。默认 12 个体中 1 个精英、11 个普通繁殖位置。

### 8.8 一代的完整顺序与停止

1. 绑定本代训练计划及不可变参数快照。
2. 按稳定种群顺序评估全部个体，精英和复制个体也完整评估。
3. 保存本代统计、个体规则身份、评估结果和最优可行候选快照。
4. 若达到 G 个已评估种群，冻结候选并进入验证，不再繁殖或轮换。
5. 否则根据本代成绩选择精英和父代，互斥选择算子并填满下一代。
6. 清除下一代旧成绩，绑定下一代计划，回到步骤 2。

父代选择只比较本代同计划成绩，不能把旧计划父代成绩与新计划子代成绩混排。正常按代数停止；其他停止原因包括无可行个体、配置/实现/基础设施错误、资源监督中断和用户取消。

首版不按目标阈值、验证进展或测试成绩早停。以后增加早停须记录数据来源及策略版本。

## 9. 候选归档、验证与最终测试

### 9.1 候选集合

每代保存本代最优可行规则对，按 `rule_pair_id` 去重，保留首次出现的稳定身份及所有出处。G 代最多 G 个候选。候选快照不能引用后续可变个体。

不同代计划不同，不按跨代训练均值直接建立历代全局最佳。若使用 DEAP HallOfFame 作为容器，须改变更新依据，不能照搬跨计划成绩排序。

### 9.2 固定验证选优

训练完成后先冻结候选集合，再将每个候选放到同一固定验证计划上完整评估。沿用 D03，全计划成功者可行；选最小验证均值，平分按候选首次出现次序。

全部候选不可行时报告 `NO_VALIDATION_WINNER`，保留证据，不打开测试集寻找替代。验证结果不回流到父代选择或训练 seed。人工根据验证结果调整超参数时，使用新实验身份，不覆盖旧实验。

### 9.3 规则冻结、测试与独立重复

选优后先写出不可变 `selected_rule.json` 及摘要，再执行预定测试计划。测试只评价这份规则；失败不触发换候选、改 seed 或调参。

每次独立 trial 分别得到自己的验证胜者，分别测试并报告。不同 trial 使用不同 evolution seed，可共享同一套训练计划序列及固定验证/测试计划，记录这一安排。

不按测试均值挑选最好的一次 trial。若以后要在 trial 间再选一条规则，必须预先声明基于验证成绩的选择规则，在最终规则冻结后才使用其测试结果。

训练、验证选优和测试分别记录状态。测试失败保留已选规则及原始结果，不能用成功子集平均掩盖。故障注入案例若按预期触发失败，可作为相应失败处理门禁的证据，但不得伪装成正常 smoke 闭环全部成功。

### 10.1 对齐层次及允许差异

### 10.4 J03：深度、节点数与尝试

统一按根到最深叶的边数高度：

| 树 | Java `depth()` | Python 高度 |
| --- | ---: | ---: |
| 单特征 `PT` | 1 | 0 |
| `(+ NIQ PT)` | 2 | 1 |
| 最深路径 8 个节点 | 8 | 7 |

\[
\text{height}_{Python}=\text{depth}_{Java}-1.
\]

Java 交叉、变异 `maxdepth=8` 对应本稿最大高度 **7**，初稿最大高度 8 已修正。每棵另检查最多 255 节点；当前仅二元函数，高度 7 的最大节点数即 `2^8-1=255`。Java 未另配节点上限，255 为本稿工程约束。

若替换位置距根 d 条边、新子树高度 h，需满足 `d+h<=7`，提交前仍检查整棵最终树及其角色、节点数和合法性。刚好达限允许，超限拒绝。

变异新子树使用 Java grow，目标高度上限 3，对应 Java grow 深度配置 4；实际允许高度 0—3。交叉与变异默认均为 1 次总尝试。变异失败返回原个体独立克隆，双树的未选树结构保持原样。

来源：`ec/gp/GPNode.java`、`ec/gp/koza/MutationPipeline.java`、交叉 `verifyPoints` 及参数文件。

### 10.5 J04：双树交叉与失败回退

先选父代 A、B，再等概率选择同一角色槽；在选中树中分别选节点，尝试交换子树，另一角色整树交换。Java 通过分别抽槽及约束匹配得到同角色配对；Python 可直接均匀选择同角色，保持有效配对分布，不复刻被拒绝的抽槽次数。

令方向 1 为“B 子树接入 A”，方向 2 为“A 子树接入 B”：

| 方向 1 | 方向 2 | 子代 1 | 子代 2 |
| --- | --- | --- | --- |
| 成功 | 成功 | A 的选中树接入 B 子树；另一树取 B | B 的选中树接入 A 子树；另一树取 A |
| 成功 | 失败 | A 的选中树接入 B 子树；另一树取 B | **完整克隆 A** |
| 失败 | 成功 | **完整克隆 B** | B 的选中树接入 A 子树；另一树取 A |
| 失败 | 失败 | **完整克隆 B** | **完整克隆 A** |

失败方向复制另一名父代的完整规则对，不是仅取消某棵树替换，也不是随机选父代。四种组合分别构造案例核验。

若配置多次尝试，固定同一对父代和角色槽，重新选择两个节点；双向均成功时提前结束，耗尽后使用最后一次两方向结果，不把不同尝试的成功方向拼接。只输出一个子代时仅以方向 1 的结果决定完成和回退。

只剩一个种群位置时只输出子代 1，仅检查方向 1，不因未输出方向失败否决。所有返回结果独立克隆，不能共享可变树。单树普通交叉仍按各自父代回退，见第 8.5 节。

来源：`mengxu/algorithm/multipletreegp/AllIndexAllSwapCrossoverPipeline.java`。

### 10.6 J05：生命周期

主训练确定使用 fresh，不增加 `java_lifecycle` 模式。Java 新建、run、rerun、reset、rotate 必须另有小型独立运行证据，状态合同见第 6.3 节。

重点核验：资源参数是否重采样、随机流是否重设、资源采样前缀是否被消费、B 在操作边界和输入生成后的值、队列及运行状态是否清空。不能以“调用了 reset”推断所有状态等同 fresh。

来源：Java `EvaluationModel`、`SchedulingSet`、`DynamicSimulation`、`SystemState` 及 B08 Context。

### 10.7 J06：繁殖、精英、代数和 seed

| 项目 | 确定方案 |
| --- | --- |
| 繁殖 | 先互斥选择算子，再产生对应数量子代 |
| 权重 | 0.80/0.15/0.05 是算子调用概率，不是子代占比 |
| 计数 | 选择次数、接纳子代数、失败回退分别记录 |
| 精英 | smoke 1 个；可行者中选；独立克隆；放末尾；清成绩后全量重评 |
| 精英不足 | 使用实际可用数，其余由正常繁殖填充 |
| 全代不可行 | 停止该次训练并保存证据 |
| 代数 | 4 表示评估 0—3 代，末代之后不再繁殖/轮换 |
| seed | 每条训练运行按 10000 步长提前展开；进化 seed 独立 |

单次 trial 的计划训练模拟数为 `12×4×2=96`，已包含精英重评。采用 10000 步长不改变 fresh 合同；清单溢出拒绝与旧轮换 API 的 long 回绕分别验证。

来源：`ec/breed/MultiBreedingPipeline.java`、`generate-max=false` 参数、精英及单树/双树演化状态的评估轮换流程。

### 10.8 独立对照证据

对照输入只包含父树、受控节点/抽样选择、运行输入和配置，不注入预期子代或预期结果。Java 与 Python 分别执行，保存实际装载树、子代、操作、状态和结果，不能把 Python 输出复制为 Java 参考。

Java 环境沿用既有 JDK17 要求。新增观察/适配补丁单独保存，不覆盖原来源；源码、依赖、编译及执行命令绑定摘要。无法执行时记录 `NOT_EXECUTED` 或基础设施错误，不能按源码阅读宣称对照通过。

结论仅覆盖实际执行的机制和案例，不延伸为任意输入等价、同 seed 曲线一致、论文数值复现或性能加速。

## 11. 配置、API 与 CLI

### 11.1 训练配置协议

`format=fogsim.training-config`、`schema_version=1`。严格拒绝未知字段、非法计数、无效权重、缺失计划或不支持的策略版本。先完成配置、模板和规则预检，再创建进化 RNG 或开始模拟。

- 最终每棵树的父代来源；成功子树替换的受体/供体及位置；回退时完整规则对来源。
- 精英的来源和实际数量，下一代规模、稳定顺序及成绩清除情况。

每代繁殖汇总与逐个体日志相互核对：普通接纳子代数加实际精英数等于下一代种群规模；失败回退仍计入接纳子代。记录算子调用概率，不能以最终子代比例反推调用权重是否正确。

小规模验收保存每条原始运行结果及可导出的输入档案；完整事件 trace 用于代表和故障案例。失败/中断档案明确 `capture_complete`、coverage 和完成范围，不伪装成完整可重放输入。

JSON 完整写出后原子替换；JSONL 只接受完整行，识别并记录中断尾行，完整快照有提交边界。保存中间记录不等于支持任意中断点续训。

### 12.3 数值和身份编码

普通指标只写有限 JSON 数字或 null，禁止裸 NaN/Infinity。诊断规则分数若需保存，使用 B08 的 f64 位串标签；不递归猜测所有数值字段的含义。此要求不会把合法特殊规则分数变成领域失败。

最终规则保存完整 B08 规则描述、身份、语义版本及 rule_manifest，不能只存 pretty print。配置、计划和源码摘要不代替规则身份；失败罚值不写回原 makespan。

### 12.4 可复现性判据

在相同 Python/DEAP 及依赖版本、实现源码、有效配置、模板、计划和 evolution seed 下，按稳定顺序执行，必须得到相同的树、谱系、计划绑定、算子操作/回退、评估可行状态、指标和验证选优结果。

只排除预先声明的实际耗时、墙钟时间戳、输出位置等观测字段；语义摘要字段清单固定。不能忽略规则、成绩、计划、运行次数或树来源差异。

不要求跨 Python/DEAP 版本随机序列相同，版本改变须重验；相同 seed 也不表示与 Java 原生随机序列相同。默认墙钟限制关闭或不触发的正常闭环用于确定性复现；触发中断的运行另作中断证据，不能伪造完整复现通过。

### 13.2 闭环规模与 848 次复现预算

| 范围 | 计划模拟次数上界 |
| --- | ---: |
| 单次 trial 训练：12 个体 × 4 代 × 2 条运行 | 96 |

| 单次 trial 训练＋验证＋测试 | 106 |
| 一种模式、两个不同 evolution seed | 212 |
| 单树和双树首跑合计 | 424 |
| 两模式完整配置各执行两遍：首跑＋同配置复跑 | **848** |

两个不同 evolution seed 检查独立重复，不能替代同配置复现。S13 要求单树完整配置执行两遍，双树完整配置也执行两遍，逐一比较对应 trial。单树批次闭环上界 424，双树批次新增闭环上界 424。

场景从既有小案例选择，使用少量资源和 recorded 工作流，单条事件预算显式。确切场景、统计计数、预算和覆盖理由随实施批次在运行前记录并冻结；必须足以触发相应多候选决策，不能只因配置写了 GP 就认定覆盖。

训练成绩改善不是强制门禁；不要求小种群战胜所有基线或达到论文数值。验收重点是公式、计划、算子、隔离、证据和可复现性。
