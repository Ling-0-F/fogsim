0.1 与 0.2 共用项目结构。预先用列表保存工作流和资源，不意味着 0.1 已经通过多设备、多工作流竞争或任意 DAG 的验收。

## 2. 0.1 应实现的行为

1. 加载固定资源与工作流，检查输入完整性。
2. 初始时钟为 0，资源空闲，任务未派发、未完成。
3. 根据到达时间产生工作流到达事件；未来工作流不能进入当前规则的可见候选信息。
4. 找到入口任务或已满足前驱条件的任务，调用路由规则。
5. 选定资源后经历上传；到达后直接开始或进入资源队列。
6. 开始执行后安排完成事件；占用计算与下载时间。
7. 完成后标记任务、更新资源和完成记录、释放后继。
8. 全部输入工作流完成后计算 makespan，并输出轨迹。

调度为非抢占式。上传采用预定延迟，不增加网络传输排队、实时带宽分摊或故障模型。

## 6. 状态设计完成与验收的区别

1.1.0 完成的是 [07](07-STATE-OWNERSHIP.md) 中状态权威位置、引用、修改职责与时机、初始值、固定重跑和不变量设计。0.1/0.2 功能范围未变，所有运行验收仍未通过。

后续检查应覆盖任务重复派发/完成保护、完成登记一致性、等待队列与两类缓存、已安排开始但未触发的预约，以及固定实例重建后不引用旧轮对象。已形成设计不等于已实现这些检查。

完整事件表、最终接口和同时刻策略仍需继续设计；预约与 Java 的等价性、缓存浮点影响及随机重置边界需要相应运行验证。
