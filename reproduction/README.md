# Java/Python 调度对照与论文表 VII 复现实验

2026-11-19 · 上游版本 `014834d` · Python 实现 `fogsim-0.4.0-B04`

在相同输入上，七种启发式算法的 Java 和 Python 实现得到了相同的任务分配及执行时间。重新生成论文场景后，各算法的性能与论文表 VII 有明显差距。下文分别给出可重查的调度事实、实测差距和采用的实验口径。

Small 单设备的 MTGP 已在 NVIDIA CUDA 和摩尔线程 MUSA 上分别完成表 VI 搜索预算。1,000 个体 × 51 代 × 30 次独立演化含验证和测试，RTX 3080 Ti 用时 2 分 40.53 秒，MTT S4000 用时 17 分 25.33 秒，逐试次输出一致。[GPU 耗时曲线与逐例结果](gpu/README.md)

## 表 VII 的实测结果

共使用 270 个场景实例，得到 1,890 条基线、810 条短训练 MTGP 和 90 条 51 代 MTGP 的测试结果。下表单位为秒，越小越好。每对冻结规则先在同一组 30 个实例上取均值，MTGP 一栏再对 3 次独立演化的均值计算平均和样本标准差。比较基线同样使用这 30 个实例。

| 场景 | FCFS 实测 | MTGP 短训练，均值 ± SD | 论文 MTGP | 实测最优手工基线 |
| --- | ---: | ---: | ---: | --- |
| Small 1 | 5065.44 | 5365.07 ± 2992.23 | 2397.09 | HEFT 4182.55 |
| Small 2 | 4677.04 | 4375.80 ± 2169.76 | 1702.01 | HEFT 3531.05 |
| Small 3 | 4775.33 | 3949.02 ± 1552.78 | 1491.17 | HEFT 3725.74 |
| Medium 1 | 7476.05 | 8207.34 ± 6185.00 | 3636.68 | SDLS 5963.21 |
| Medium 2 | 7059.12 | 3748.97 ± 159.71 | 2265.32 | SDLS 5832.19 |
| Medium 3 | 7891.25 | 7345.09 ± 4551.54 | 1930.73 | SDLS 5752.99 |
| Large 1 | 12528.06 | 14779.20 ± 12509.97 | 6242.00 | SDLS 10078.40 |
| Large 2 | 11683.51 | 12020.33 ± 11249.49 | 3562.01 | SDLS 9577.37 |
| Large 3 | 12020.62 | 6954.39 ± 2000.84 | 2633.26 | HEFT 10083.85 |

**Small 1 延长训练。** 32 个体、51 代的 3 次独立演化分别得到 2497.30、3037.71、3117.59 秒，均值 **2884.20 ± 337.44 秒**。相对同实例 FCFS 缩短 43.1%，比本次最优手工基线 HEFT 也短；比论文 MTGP 均值 2397.09 秒仍长 20.3%。短训练在 Medium 2、Large 3 两个场景取得低于全部七种基线的均值。其他场景与种子之间的差异见上表。本次预算没有复现论文的九场景全面优势，3 次演化也不足以重做论文基于 30 次独立演化的 Wilcoxon 显著性结论。

**基线偏差具有规律。** MaxMin 的九场景均值与表 VII 的偏差均在 7.1% 以内；FCFS 则全部高于表 VII，幅度为 24.3%–84.5%。BWAWA 和 CEAS 在九个场景中各自取两位小数后的实测均值相同。原 Java 的 BWAWA 给本地选项的带宽代价为零；CEAS 的路由效用使用本任务可取得的最快计算时间，加上该选项的通信时间。本地执行的通信时间为零，两者都会选本地。论文为两者报告了不同的均值，现有证据不能把全部差距归因于概率笔误或 GP 预算。

## Java/Python 对照

| 本次实际执行 | 比较内容 | 结果 |
| --- | --- | --- |
| Python 基础测试 | 事件、队列、DAX、工作流生成、动态计数、模拟内核和 GP 特征 | 181 通过，0 失败或跳过 |
| 14 个固定案例和 96 个生成案例 | 输入和候选顺序、事件前后状态、调度决策、动作与最终记录。B04 的时间容差为绝对 1e−9、相对 1e−12 | 每种语言 3,469 个事件、2,021 个决策，全部通过 |
| 3 个动态 GP 对照 | Java 生成输入，Python 重放；覆盖链、共享资源分叉汇合、禁用本地计算 | 104 个事件、75 个决策，3/3 通过 |
| 双树算子 | 相同受控条件下产生的子树交换、整树交换、变异等结果 | 38/38 通过 |
| 七种基线，两个固定输入 | 用原 Java 算法逐任务比对资源、派发、到达、开始、计算完成、最终完成时间和执行计划 | 113 任务的争用案例和 847 任务的完整 Small 2 实例，各 7/7 完全相同 |
| 实验用 GP 求值与选择 | 4 个固定案例 × 4 对规则，对照 B04 原入口，含受保护除法、有符号零、同分与队列特征 | 16/16 完整调度相同 |

Small 2 使用测试种子 90000。七种算法由 Java 单独计算的去预热 makespan，与发布的 Python 逐实例 CSV 数值逐一相同。B04 构建时使用的 647 份 Java 源文件与仓库根目录的原 Java ZIP 对应文件逐字节相同。数据适配器负责注入输入和观察执行；排序、事件处理和基线优先级的 Java 实现直接来自原源码。Small 1 的首个短训练试次也用最终脚本独立重跑了一次，规则、验证记录和 30 个测试结果均逐字节相同。

**已知边界。** 当起始时间达到 2⁵³，浮点加法可能丢掉正的执行时长。负例中 Python 显式报错，Java 跑到了结束，但两个执行区间发生重叠。另有两种人工构造的预约队列状态，两端的准入判断不同；正常案例中的 395 次预约探测结果一致。动态算例使用共同输入；两端独立随机生成、独立演化产生的树不要求逐种子一致。[逐项证据](results/verification/) · [双方原始调度样本](results/verification/baseline-schedule-evidence.zip)

## 实验设置

| 项目 | 采用的取值和依据 |
| --- | --- |
| 表 V 场景 | Small、Medium、Large 分别使用 10/20、15/30、25/50 个预热/测量工作流。每种规模设 1、2、3 部移动设备。边缘/云服务器分别为 20/20、30/30、60/60 |
| DAG | 分别从 A、A+B、A+B+C 的 5、10、15 份 DAX 等概率抽取。沿用实际 XML。Sipht 的 A/B/C 类文件实际含 29/58/97 个任务，论文标为 30/60/100；Epigenomics B 实际为 47，论文标为 46 |
| 到达和测量窗口 | 每部设备独立生成指数间隔，到达间隔均值 100 秒取自 Java。把到达按时间合并，前一批只作预热并参与资源争用。全部工作流完成后，按式 (2) 用测量批最后完成时间减去该批首次释放时间。B04 原动态模式的历史截止条件单独在对照测试中保留 |
| 处理和通信 | 处理速率按表 IV 分设备/边缘/云均匀抽取，分别为 [125,250]、[250,500]、[500,1000]。工作量均匀抽自 [5000,15000]。按 VII-A 为每任务分别独立抽取 [5220,20680] 的整数输入量、输出量，作为总传输量。这里的独立性为实验假设。B04 原生成器另行抽取基础数据和依赖边数据 |
| 表 IV 笔误 | 按原表档位顺序，128/256/512 的概率取 0.2/0.6/0.2。原 Java/B04 用累积阈值 0.2、0.8，但在相应区间返回 256/512/128。两种映射使最常见的带宽分别为 256 和 512。论文实验仅在场景生成器中修正。边缘带宽 1024，各服务器上下行分别取样，跨设备共享 |
| 七种基线 | HEFT、FCFS、MaxMin、MinMin、SDLS、BWAWA、CEAS。优先级和同分处理遵循随论文提供的 Java 代码。每场景固定测试种子 90000–90029；各方法共享完全相同的工作流到达、依赖、任务量和资源 |
| 双树 GP | 使用 B04 的双树初始化和遗传算子，排序、路由各一棵树。表 II 的十个终端，四则运算与 Max/Min，除以零返回 1。初始化深度 2–6，最大深度 8，按节点层数计。交叉/变异/复制为 0.80/0.15/0.05；交叉或变异选择非终端节点的概率为 0.9 |
| 训练与选树 | 每代全种群共用一个训练实例，换代更新实例；各代最优规则用独立的 3 个固定验证实例选优。每个演化种子仅冻结一对规则，然后评估 30 个测试实例。三个种子间不按测试成绩选冠军 |
| 实际训练预算 | 九场景均执行 8 个体 × 3 代 × 3 个独立演化种子，精英 1。另在 Small 1 执行 32 个体 × 51 代 × 3 个种子，精英 2。两组使用 B04 默认锦标赛大小 3。论文使用 1000 个体 × 51 代 × 30 次，精英 10；表 VI 未给出锦标赛大小，配套 Java 设置为 7 |

事件、资源队列、任务就绪判定、同刻事件顺序与执行记录使用 B04 的 Python 模拟内核。有限到达流提前生成，每个工作流在释放时才进入可见状态。为运行标准规模，每个候选项的只读规则打分省略整张对象图的前后指纹扫描；实验使用内置规则和解析过的 GP 表达式。表中的两组固定输入及独立 GP 对照覆盖了这条执行路径。
